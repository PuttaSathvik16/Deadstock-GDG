# 1. Frontend — **Next.js + React + TypeScript**

### Use:

**Next.js 16.x + React + TypeScript**

Next.js is currently a full-stack React framework, so it lets you keep the UI and server-side API logic in one project instead of creating a separate frontend/backend application. ([Next.js][1])

### Why?

Because you need a fairly sophisticated UI:

* camera capture
* material cards
* inventory
* constraint editor
* AI generation
* live collaboration
* design canvas
* activity feed

And you're going to be building quickly.

### Why TypeScript?

Because our system has lots of structured objects:

```text
Material
Inventory
Constraint
Design
Decision
Session
Participant
```

TypeScript will prevent a lot of stupid integration bugs during the hackathon.

# 4. AI — **Google Gemini API**

This is the **brain of the application**.

The current Gemini API supports multimodal inputs, structured outputs, function calling, and image understanding/generation capabilities. Google's current documentation also recommends the **Interactions API** as the default interface for new Gemini projects as of June 2026. ([Google AI for Developers][2])

For this project I'd structure Gemini into **four jobs**.

### Gemini A — Material Vision

Input:

```text
camera frame / image
```

Output:

```json
{
  "material_type": "denim",
  "color": "navy",
  "pattern": "solid",
  "texture": "medium",
  "confidence": 0.93
}
```

---

### Gemini B — Material Normalization

Turn messy AI observations into our internal model:

```text
MAT-001
MAT-002
MAT-003
```

with:

* type
* color
* texture
* quantity estimate
* confidence
* source image
* user corrections

---

### Gemini C — Constraint Reasoning

Example:

```text
AVAILABLE MATERIALS:
3 denim panels
2 linen panels
1 satin panel

REQUEST:
3 evening outfits
```

Gemini determines:

> Look 1 valid
> Look 2 valid
> Look 3 requires unavailable material

This is where the project becomes more than an image generator.

---

### Gemini D — Fashion Concept Generation

Gemini generates:

* silhouette
* garment type
* material allocation
* design rationale
* image/concept

But **the generated design cannot be accepted until it passes our constraint validator**.

That distinction matters.

---

# 5. Constraint Engine — **TypeScript**

This should NOT be entirely inside Gemini.

This is very important.

We need a deterministic layer.

### Gemini says:

> “This design uses 4m denim.”

Our application checks:

```text
Available denim = 3m

Required = 4m

RESULT = INVALID
```

That's our own rule engine.

So architecture becomes:

```text
Gemini
  ↓
AI proposal
  ↓
Constraint Engine
  ↓
VALID / INVALID
  ↓
UI
```

This makes the product more trustworthy.

# 8. Supabase Realtime

This will be extremely useful for our collaborative studio.

Supabase Realtime supports database-change subscriptions, Broadcast and Presence, so clients can synchronize application state and participant activity over real-time channels. ([Supabase][4])

For example:

### User A removes fabric

```text
User A
 ↓
Supabase
 ↓
Broadcast
 ↓
User B
 ↓
UI updates
```

### Shared activity

```text
SATHVIK removed MAT-003
```

Everyone sees it.

# 9. Video — **Vonage Video API**

This is the second major pillar.

Use the **Vonage Video API JavaScript SDK** for the browser.

Vonage's current Video API uses session IDs and tokens, with the client connecting and publishing/subscribing to live streams through its SDK. The JavaScript SDK is actively maintained; the current September 2026 release is 2.35.2. ([Vonage Developer][5])

### Our implementation:

```text
Designer
     │
     ├──────────────┐
     │              │
     ▼              ▼
Camera          Microphone
     │              │
     └──────┬───────┘
            │
         Vonage
            │
      ┌─────┴─────┐
      │           │
 Designer A   Designer B
```

Inside our app:

```text
┌──────────────────────────────────────┐
│ LIVE STUDIO                          │
├─────────────────┬────────────────────┤
│                 │                    │
│   VIDEO CALL    │  MATERIAL BOARD    │
│                 │                    │
│   A             │  MAT-001           │
│   B             │  MAT-002           │
│                 │  MAT-003           │
├─────────────────┴────────────────────┤
│ AI DESIGN / CONSTRAINTS / DECISIONS  │
└──────────────────────────────────────┘
```

Vonage supports real-time interactive video, so this is a natural fit for the live collaboration part. ([Vonage Developer][6])

# ⚡ One important architecture rule

Don't let Gemini directly control the truth.

Use:

```text
               GEMINI
                 ↓
          AI INTERPRETATION
                 ↓
        ┌──────────────────┐
        │ CONSTRAINT ENGINE │
        └────────┬─────────┘
                 ↓
          SYSTEM OF RECORD
                 ↓
              SUPABASE
                 ↓
        ┌────────┴────────┐
        ↓                 ↓
      DESIGN            COLLAB
                          │
                        VONAGE
```

### Gemini says what it *thinks*.

### Your constraint engine decides what is *allowed*.

### Supabase remembers what is *true*.

### Vonage lets humans decide what happens *next*.

**That architecture is much stronger than “Gemini generates an image.”**

And it gives your team a very clean division of work: **AI engineer, frontend/UI engineer, backend/constraint engineer, and Vonage/realtime engineer.**
